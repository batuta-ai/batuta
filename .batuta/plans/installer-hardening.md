## Decisions and context

Node 22, CommonJS, standard library only, one file. Every test in `tests/install.test.js` injects its dependencies (`fetch`, `exec`, `binDir`, `platform`, `arch`, `baseUrl`, and the `paths` of `installSharedSkills`): no network, no real CLI, temp directories under `os.tmpdir()` removed at the end of each test. Test names must contain the pattern their proof greps for (`--test-name-pattern` is a regular expression over the test name). Do not edit `.github/`, `skills/`, `skills-lock.json`, `CHANGELOG.md` or the release-please files. README.pt-BR.md mirrors README.md paragraph by paragraph: every README change lands in both files, in the same place. Environment setup is never a question; the sandbox allows writes under the worktree and `$TMPDIR`.

**Task 1.** `downloadCore` gains `deps.timeoutMs` (default 60000) and `deps.maxBytes` (default 64 MiB). Each request passes `{ signal: AbortSignal.timeout(timeoutMs) }` to the fetcher; an abort surfaces as `download of <name> timed out after <ms> ms`. Bodies are read through one helper: when `response.headers` reports a `content-length` above the cap fail with `<name> is <n> bytes, above the <cap> limit` before reading; otherwise read `response.body` chunk by chunk (`for await`) and fail with the same message the moment the total exceeds the cap; a response without `body` falls back to `arrayBuffer()` (the older fakes). Tests build real `Response` objects (`new Response(bytes, { status, headers })`) so the stream path is exercised, and a fake fetch that only settles on its signal's `abort` event covers the deadline with `timeoutMs: 20`. The existing `finally` already removes the work directory; the test for "leaves nothing behind" asserts the work directory pattern `batuta-core-*` and `.batuta.*` staging files are absent from `os.tmpdir()` and `binDir` after each failure (deadline, size cap, checksum mismatch, tar failure).

**Task 2.** Add `const CORE_CHECKSUMS = { ... }` right after `CORE_VERSION`, one entry per release asset, with these values for v1.1.0-beta.20 (from the release's checksums.txt, verified by the conductor):
`batuta_darwin_amd64.tar.gz`: `be8ef923041586ce380dab17f56d840d95f4c940468d894115d6d459302db207`;
`batuta_darwin_arm64.tar.gz`: `03ff5783225a000ee89f9f9a55ee738e4295a4618158d043a0c8f993b8c8188e`;
`batuta_linux_amd64.tar.gz`: `f582180fc6b030bd94ad77dd833aa8da178f75b97a53cd952bb1008d19a85a5c`;
`batuta_linux_arm64.tar.gz`: `a7af84139570e3b0ca2ee76e5425f831e40a8c8060f466ff227ebb90a396552b`;
`batuta_windows_amd64.zip`: `34de4761a87cdf3816aa9d031d0f96ecd71811af89acd63618476e01748d4e6c`.
`downloadCore` takes the pin from `deps.checksums || CORE_CHECKSUMS` (tests inject their own map): no pin → `no pinned digest for <asset> in this package`; `checksums.txt` still downloaded and must list the same digest, otherwise `checksums.txt of <version> lists <x> for <asset>, this package pins <y>`; then the archive's sha256 must equal the pin. `scripts/pin-core.sh <tag> [--from <checksums file>]` (bash, curl for the download, `node -e` for the in-place rewrite of both constants, executable bit set) prints `commit as: fix(install): pin core <tag>` like `scripts/sync-skills.sh` does for the skills. `tests/fixtures/checksums.txt` is a five-line fixture with fake digests; `tests/pin-core.test.sh` copies `bin/install.js` to a temp file, runs the script with `--from` against the fixture and `INSTALL_JS=<temp copy>`, and greps the rewritten constants (the script honours `INSTALL_JS` for its target, default `bin/install.js`). README sentence (line ~53 in both files): the archive is checked against the digest pinned in this package and the release's `checksums.txt` (PT-BR: "o digest fixado neste pacote").

**Task 3.** `coreAsset` maps `win32`/`x64` to `batuta_windows_amd64.zip` (windows arm64 is not shipped: null). A helper `coreBinaryName(platform)` returns `batuta.exe` on win32 and `batuta` elsewhere; `installBinary(bytes, binDir, name)` and `installCore`'s target, version probe and `go install` check use it. Extraction stays one `tar` call: `tar -xf <archive> -C <work> <member>` works for both tar.gz and zip with bsdtar, which Windows 10 1803+ ships as `tar.exe`; the error for a missing tar names `tar.exe` on win32. The existing win32 assertion `/no prebuilt batuta/` moves to an unsupported pair (`freebsd`/`x64`). README "no Go needed" becomes "no Go needed on Linux, macOS and Windows 10 or later (x64)" in both languages, same paragraph.

**Task 4.** `installSharedSkills` computes a content hash per vendored skill (`treeHash(dir)`: sha256 over the sorted relative paths and file bytes) and writes `lock.hashes = { <name>: <hex> }`. Before replacing `<dst>/<name>`: when the previous lock has a hash for that name and `treeHash` of the installed directory differs, the directory was customized: keep it, print `  kept <name>: customized locally; rerun with --force-skills to replace it`, and carry the previous hash forward so the warning repeats until the user decides. No previous hash (a lock older than this change) means replace, as today. Retirement of a dropped skill applies the same rule: retired only when its hash still matches. `--force-skills` (new flag in `USAGE_LINES`, parsed in `main`, passed as `paths.force`) replaces and retires regardless. The installer never touches a project's `.agents/skills`; copies rewritten by the skills CLI (`npx skills update`) change their hash and are therefore treated as customized. README: a section "Shared skills: who owns what" after the paragraph on `~/.agents/skills` stating those four rules; PT-BR mirror "Skills compartilhadas: quem é dono do quê".

**Task 5.** Translate `docs/specs-history/PRD-v1.md` from Portuguese to English in place: same headings in the same order, same tables, code blocks and links untouched, dates and version numbers unchanged. Line 3 is the epigraph `> *Quem rege não toca.*`: keep it as is and append the English gloss on the same line, `> *Quem rege não toca.* — the one who conducts does not play.` Do not summarize, do not modernize the content (it is history; "Batuta v1" statements stay as written), do not add a translator's note. The proof forbids the listed Portuguese function words anywhere except line 3, so read the result once end to end before finishing.
